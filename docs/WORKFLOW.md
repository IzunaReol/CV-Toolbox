# 工作流说明 / Workflow

本文对应 v2.2.0，描述当前输入输出约定。安装与启动见 [README](../README.md)，版本变化见 [CHANGELOG](../CHANGELOG.md)。

## 运行模式

| 模式 | 输入 | 成功输出 |
|---|---|---|
| 全流程（标准） | 视频、检测模型 | 抽帧图片、标注图片、MP4、推理统计 |
| 全流程（仅保存最终视频） | 视频、检测模型 | MP4、推理统计 |
| 仅抽帧 | 视频、抽帧间隔 | JPG 图片 |
| 仅推理 | 图片、检测模型 | 标注图片、推理统计 |
| 仅合成 | 图片、可选源视频 | MP4 |
| 文件浏览 | 已有任务工件 | 预览、下载、确认删除 |

视频上传支持 MP4/MOV/AVI/MKV；图片支持 JPG/JPEG/PNG/BMP/WebP/TIF/TIFF，后缀大小写不敏感。模型用于目标检测，按 Ultralytics YOLO 接口加载 `.pt` 权重。

## 处理流程

```text
标准全流程：视频 → 抽帧 JPG → 图片推理与标注 → 合成 MP4
流式全流程：视频 → 逐帧解码、采样、推理、标注、写入 MP4
                                    └→ 推理统计
```

Web UI 经后台任务管理器调用 `web/pipeline.py`，编排层加载 `scripts/` 中的处理函数，不进入 CLI 交互入口。图片格式与视频写入校验由 `web/media.py` 共用。

### 抽帧

从第 0 帧开始，每 N 帧保存一帧；N 必须为正整数。CLI 输出命名为 `frame_000000.jpg`，Web 流程增加任务名前缀。中文路径使用图片编码后写入的方式处理，并检查文件已落盘。

### 推理

批次内复用一个模型实例。每张图片解码一次后用于推理和标注，字体按字号缓存。图片按文件名排序，绘制指定类别、颜色、标签与置信度。

| 参数 | 默认值 | 含义 |
|---|---|---|
| `conf_thres` / CLI `--conf` | 0.25 | 置信度阈值 |
| `iou_thres` / CLI `--iou` | 0.45 | NMS IoU 阈值 |
| `device` / CLI `--device` | `auto` | Web 提供 auto、cpu、cuda |
| `box_color` / CLI `--color` | 红色 | 颜色名、BGR 三元组或十六进制颜色 |
| `label_map` / CLI `--label-map` | 无覆盖 | 类别 ID 到显示名称的映射 |
| `classes` / CLI `--classes` | 全部类别 | CLI 支持类别 ID 或名称，Web 提供多选 |

Web 未选择任何类别时不能开始推理。仅推理遇到无法解码的图片时跳过并记录失败数量；全部图片无法读取时任务失败。模型执行或写入异常会使当前任务失败。标准全流程存在无法读取的帧时停止合成，避免静默丢帧。

### 合成与帧率

| 场景 | 输出 FPS |
|---|---|
| 全流程选择原视频帧率 | 源视频 FPS |
| 仅合成选择原视频帧率，并上传源视频 | 所上传源视频的 FPS |
| 仅合成未上传源视频 | 30 |
| 自定义帧率 | 使用指定正数，支持小数 |
| CLI 合成 | `--fps` 指定值，默认 30 |

帧率不根据抽帧间隔换算。30 FPS 视频每 5 帧取一帧，再按 30 FPS 合成，时长约为原视频的五分之一。无法取得有效源帧率时，元信息读取函数回退到 30 FPS。

图片按文件名升序写入，不做自然数排序；建议将序号补零，例如 `frame_000001.png`。损坏或尺寸不一致的图片使合成失败。

视频先写同目录临时 MP4，完成后校验编码器、文件大小、帧数、首帧与尾帧，再原子替换目标。异常或取消清理临时文件，已有目标视频不受影响。

## 上传、隔离与清空

- 每次视频上传分配独立 ID；重复任务使用新输出目录。图片任务与批次采用时间戳加随机后缀，避免同秒重名。
- 模型按完整 SHA-256 内容摘要保存并原子写入。启用跨会话缓存时保存在 `uploads/models/`，否则保存在 `outputs/_models/`。
- 每个上传框有独立“清空已上传”按钮，只重建当前框。清空模型同步重置模型路径与类别状态。
- 已提交任务使用磁盘快照。清空上传、重新上传同名模型或清空页面结果不会取消它。
- “重置页面”重置界面；“清空结果”移除当前页面结果列表；二者不删除磁盘文件。
- “清空本地文件”清理 `outputs/` 并保留 `_models/`。运行中不允许清空或删除工件，清理失败明确提示未删除项。
- `uploads/` 中的素材不会随清空上传或清空结果自动删除，需按本地保留需求管理。

## 任务状态与统计

同一时间运行一个批次，批次内串行处理视频。单视频失败后继续后续视频；取消会停止当前任务并跳过批次剩余视频。

- 状态包括 `queued`、`running`、`cancelling`、`completed`、`failed`、`cancelled`、`interrupted`。
- 页面约每秒读取后台状态；批次进度最多每 0.5 秒落盘一次，阶段变化和终态立即保存。
- 服务未停止时，刷新页面可恢复活动批次跟踪；服务重启会中断任务，遗留运行状态在读取时标为 `interrupted`，不能从断点自动续算。
- 标准模式取消后保留已生成中间图片；流式模式不发布未完成视频。推理统计在该推理步骤成功结束后保存。
- 任务时间按东八区展示。`_meta/task.json` 保存配置与摘要；`inference_stats.json` 和 `inference_images.csv` 保存汇总及逐图统计。

统计文件存放在本地内部目录，不在普通文件浏览及工件 ZIP 中展示。

## 输入输出目录

```text
uploads/
├── <视频名>_<ID>/video.mp4
└── models/<模型名>_<SHA256>.pt
outputs/
├── <任务ID>/
│   ├── _uploaded/             # 仅推理/仅合成上传的图片
│   ├── frames/                # 标准全流程或仅抽帧的 JPG
│   ├── annotated/images/      # 标准全流程或仅推理的标注图片
│   ├── <任务ID>.mp4           # 全流程或仅合成的成品
│   └── _meta/                 # 任务配置及推理统计
├── _models/                   # 未启用跨会话缓存的模型
├── _src/                      # 仅合成时用于读取 FPS 的源视频
├── _jobs/                     # 后台批次状态、工件修订号
└── _downloads/                # ZIP 缓存
```

各任务只包含对应模式的产物。流式全流程不生成 `frames/` 和 `annotated/`。运行时目录不纳入 Git。

## 下载与工件浏览

- 每个成功任务独立下载。页面有至少两个成功全流程视频时提供“下载全部 ZIP”，打包当前页面结果；全流程只包含最终视频。
- 点击下载后才读取文件或生成 ZIP；ZIP 按输入路径、大小和修改时间复用磁盘缓存。
- 文件浏览限制在 `outputs/` 的公开任务工件，隐藏内部模型、源视频、任务元数据和缓存目录。
- 图片每页 24 张，支持大图导航、选择、单图下载与确认删除；损坏图片显示无法预览。
- 选择不超过 5 个文件且总大小不超过 20 MiB 时逐个下载；超过阈值时提供 ZIP 准备进度。
- 删除范围限制在当前任务目录，拒绝符号链接。删除后清理空目录；运行中阻止删除。

## 三段式 CLI 脚本 / Three-Step CLI Scripts

从项目根目录运行，将素材路径和类别替换为实际值。命令均为单行，可用于 PowerShell 或 Bash。

```bash
python scripts/1_frame_extract.py --video "input.mp4" --output "outputs/demo/frames" --interval 1
python scripts/2_model_infer.py --model "model.pt" --input "outputs/demo/frames" --output "outputs/demo/annotated" --classes "0" --color red --label-map "0:人"
python scripts/3_images_to_video.py --input "outputs/demo/annotated/images" --output "outputs/demo/demo.mp4" --fps 29.97
```

抽帧必须提供 `--video` 和 `--output`，`--interval` 默认 1。推理和合成保留交互式输入，也可通过参数完整指定。各脚本支持 `--help`。

抽帧和推理重跑时请更换 `demo` 目录名：输出目录已有对应结果图片时会拒绝继续，防止历史帧混入。CLI 合成不查找源视频，需显式设置所需帧率。

## 使用边界

- 当前是本地单工作线程工具，模型性能取决于实际硬件与 PyTorch 环境；跨会话文件缓存不是常驻 GPU 模型缓存。
- 输出使用 OpenCV `mp4v` 编码，无源音轨，不重建可变帧率时间戳。
- 标准流程使用 JPEG 中间帧；流式流程直接处理解码帧，两者像素与检测结果可能略有差异。
- 中文标签依赖系统 CJK 字体；缺失时安装代码支持查找的字体后重试。
- 视频验证检查帧数及首尾帧，不是对每个编码帧的完整解码审计。
- 现有自动测试使用真实媒体 IO 和替代检测模型；真实模型效果与 GPU 性能需要手工验证。
