# CV Toolbox v2.2.0

本次更新集中修复输入与历史结果混用问题，并减少视频处理中的重复加载和磁盘读写。

## 新功能

- 选择“原视频帧率”直接使用源 FPS 合成，不根据抽帧间隔换算，支持 29.97、23.976 等小数帧率。
- 所有上传框新增独立的“清空已上传”按钮，可连续更换文件而不刷新浏览器；清空模型同步清掉类别选择。
- 新增“仅保存最终视频（减少磁盘占用）”。逐帧完成解码、推理和合成，成功后保存视频与 JSON/CSV 统计。

## 可靠性修复

- 同名、同大小视频每次上传独立保存，重复任务不会混入历史帧；图片任务与批次 ID 增加随机后缀，避免同秒重名。
- 运行中阻止清空本地文件和删除工件；清理失败明确提示未删除项。
- 模型采用完整 SHA-256 内容寻址和原子写入，更换同名权重不影响已经运行的批次。
- JPG/JPEG/PNG/BMP/WebP/TIF/TIFF 在上传、推理、计数、浏览与 ZIP 下载中统一支持。
- 视频先写临时文件，通过编码器、文件、帧数和首尾帧校验后才发布成品。失败或取消时清理临时视频，已有成品不受影响。
- 合成遇到损坏或尺寸不一致图片时明确失败；仅推理跳过无法解码的图片并记录数量，全部损坏时任务失败。
- 抽帧命令行支持 `--video`、`--output`、`--interval`；抽帧和推理拒绝复用已有结果图片的目录，避免历史结果混入。

## 性能优化

- 批次内复用模型，图片解码一次后用于推理和绘图，字体按字号缓存。
- 后台进度每 0.5 秒最多落盘一次，阶段切换与结束立即保存。
- 减少逐帧日志，提交新任务时回收已结束任务的内存引用。

## 升级说明

- 无需迁移或删除历史任务；旧输出仍可在文件浏览中查看。
- 使用原视频帧率时，抽帧间隔 N 对应的视频时长约为原视频的 1/N；需要其他输出帧率时使用自定义帧率。
- CLI 重跑时请指定新的抽帧、标注输出目录。
- 流式模式不保留中间图片；取消后不保留未完成的视频。
- 输出仍为无音轨 MP4；不重建可变帧率时间戳。标准流程会经过 JPEG 压缩，流式流程直接处理视频解码帧，因此像素和检测结果可能略有差异。
- 本地 50 项回归测试通过，包含真实图片/MP4 IO、上传框重复清空、帧率、流式取消、删除保护与 CLI；检测模型使用替代实现，GPU 速度收益需在实际环境验证。

安装与运行方式保持不变：

```bash
python -m pip install -r web/requirements.txt
python -m streamlit run web/app.py --server.maxUploadSize 1024
```

升级后请重启服务。完整使用说明见 [README](https://github.com/IzunaReol/CV-Toolbox/blob/v2.2.0/README.md)，输入输出约定见 [工作流说明](https://github.com/IzunaReol/CV-Toolbox/blob/v2.2.0/docs/WORKFLOW.md)。
